# Stage 1 (Core Loop) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A playable Windows build of Streetwear Tycoon with money, time, Design Lab, factories, webshop, simple drops, HQ upgrades, bankruptcy, saving and synthesised SFX.

**Architecture:** A pure, deterministic TypeScript engine (`src/engine`, no DOM) owns all game rules; a small store (`src/store`) runs the clock and turns engine events into feed items and sounds; React UI (`src/ui`) renders it; Electron (`electron/`) hosts the UI and writes save files. The same UI runs in a browser for automated play-through tests.

**Tech Stack:** TypeScript 5, React 18, Vite 5, Vitest, Playwright (pre-installed Chromium), Electron, electron-builder (Windows portable target), @fontsource fonts, Web Audio API.

**Spec:** `docs/superpowers/specs/2026-11-26-streetwear-tycoon-design.md`

## Global Constraints

- All in-game text English; no real brand, artist, store or person names.
- No audio samples; every sound synthesised at runtime.
- Engine code must not import from `src/ui`, `src/store`, `src/audio`, or touch `window`/`document`.
- Engine is deterministic: all randomness from `state.rngState` via `src/engine/rng.ts`.
- Time: 1x = 2000 ms per day, 2x = 1000 ms, 4x = 500 ms. Week = 7 days, season = 13 weeks.
- Difficulty table, reference prices, unit costs, material multipliers, factory table, HQ table: exactly as spec §6.2, §6.5, §6.6, §6.9.
- Purchases never make cash negative; only weekly bills can.
- Save format carries `version: 1`.
- Window default 1600×900, minimum 1280×720.

## Review Focus

1. Ordering more than free warehouse space (stock + incoming) → refused with a clear reason. (Task 3 test `refuses order beyond capacity`.)
2. Drop scheduled for stock that is delayed past drop day → drop postponed, not crashing or selling phantom stock. (Task 4 test `postpones drop when stock is late`.)
3. Loading a corrupt or foreign save → refused with an error, game state untouched. (Task 5 test `rejects corrupt save`.)
4. Price set to 0 or absurd values / empty brand name → clamped/refused in engine actions. (Task 4 test `clamps listing price`, Task 1 test `rejects bad brand name`.)
5. Window closed mid-game → autosave written before exit. (Task 9 electron smoke test checks save file exists after close.)

### Task 1: Scaffold, RNG, content, calendar, new game

**Files:** `package.json`, `tsconfig.json`, `vite.config.ts`, `index.html`, `src/engine/{types,rng,content,calendar,newGame,index}.ts`, `src/engine/__tests__/core.test.ts`

**Interfaces (produces):**
- `rng.ts`: `nextFloat(state: GameState): number` (mulberry32 on `state.rngState`), `randInt(state, min, max)`, `chance(state, p): boolean`, `pick<T>(state, arr: T[]): T`, `poisson(state, lambda): number`, `seedFromString(s: string): number`.
- `content.ts`: `GARMENTS`, `COLORS`, `PATTERNS`, `EMBLEMS`, `FONTS`, `MATERIALS`, `FACTORIES`, `HQ_LEVELS`, `DIFFICULTIES` records keyed by id, plus `TASTE` (Budapest static taste per colour/pattern/garment, 0..1) and `SEASON_DEMAND[garment][season]`.
- `calendar.ts`: `dateInfo(day: number): { day, dayOfWeek, week, season: 'Spring'|'Summer'|'Fall'|'Winter', seasonIndex, year, label }`.
- `newGame.ts`: `createNewGame(opts: { brandName: string; logo: LogoChoice; difficulty: DifficultyId; seed?: number }): GameState` — throws `Error` for brand names outside 2–18 chars after trim.

- [ ] Tests: `calendar day 1 is Spring Y1 Monday`, `day 92 is Summer`, `day 365 is Spring Y2`; `rng same seed same sequence`; `new game cash per difficulty` (25000/12000/6000); `rejects bad brand name`.
- [ ] Run, see fail; implement; run, see pass; commit.

### Task 2: Design maths

**Files:** `src/engine/design.ts`, `src/engine/names.ts`, test `design.test.ts`

**Interfaces:**
- `createDesign(state, input: DesignInput): Design` (adds to `state.designs`, assigns id).
- `designQuality(design, factoryId): number` (material quality + factory mod, clamp 0..100).
- `marketFit(state, design): number` (0..1, from TASTE and season).
- `fairPrice(state, design, factoryQuality): number` = refPrice × (0.6 + q/100×0.8) × (0.85 + rep/100×0.3).
- `unitCost(state, design, factoryId): number` = base × material mult × factory mult × difficulty cost.
- `appeal(state, design, quality): number` (0.2..2).
- `randomDesignName(state, garmentId): string`.

- [ ] Tests: `luxe costs more than basic`, `premium factory raises quality`, `fair price grows with quality and reputation`, `puffer fits better in winter than summer`, `appeal stays within 0.2..2`.

### Task 3: Production

**Files:** `src/engine/production.ts`, test `production.test.ts`

**Interfaces:**
- `placeOrder(state, { designId, factoryId, quantity }): ActionResult` (`{ ok: true } | { ok: false; reason: string }`). Validates MOQ, cash, capacity. Stores `ProductionOrder { id, designId, factoryId, quantity, quality, unitCost, orderedDay, etaDay }`.
- `freeCapacity(state): number`.
- `processProduction(state, events: GameEvent[]): void` — per day: delay rolls, arrivals into `state.inventory[designId]` (`{ units, quality }`), defect write-offs, scandal rolls.

- [ ] Tests: `charges cash on order`, `refuses order beyond capacity`, `refuses below minimum order`, `refuses without cash`, `order arrives at eta`, `cheap factory produces defects over many orders (seeded)`.

### Task 4: Webshop and drops

**Files:** `src/engine/webshop.ts`, `src/engine/drops.ts`, tests `webshop.test.ts`, `drops.test.ts`

**Interfaces:**
- `setListing(state, designId, price: number, active: boolean): ActionResult` — price clamped 1..10000, rounded.
- `dailyVisitors(state): number`; `expectedDailySales(state, designId): number`.
- `simulateWebshopDay(state, events)` — Poisson sales per listing limited by available (non-reserved) stock; revenue minus platform cut (5%); followers grow.
- `scheduleDrop(state, { designId, units, price, daysAhead }): ActionResult` — 3..14 days, one active drop, units ≤ stock + incoming arriving before drop day.
- `postTeaser(state): ActionResult` — $150 × difficulty cost, once per day.
- `processDrops(state, events)` — daily hype build; on drop day resolves SOLD_OUT / SOLID / FLOP, or postpones (3 days, −30% drop hype) when stock short.

- [ ] Tests: `clamps listing price`, `cheaper price sells more on average`, `no sales without listing`, `hyped drop sells out`, `overpriced drop flops`, `postpones drop when stock is late`, `teaser once per day`.

### Task 5: Finance, HQ, tick, save

**Files:** `src/engine/{finance,hq,tick,save}.ts`, tests `finance.test.ts`, `save.test.ts`

**Interfaces:**
- `chargeWeeklyBills(state, events)` — rent, $40 platform fee, storage $0.15/unit/week (×difficulty cost).
- `updateSolvency(state, events)` — overdrawn countdown by difficulty grace; `state.gameOver = { reason: 'bankrupt', day }`.
- `upgradeHQ(state): ActionResult`.
- `advanceDay(state): GameEvent[]` — order: day++, production, drops, webshop, weekly bills on dayOfWeek 0, solvency, hype decay, stats.
- `serialize(state): string`, `deserialize(text): GameState` (throws on bad JSON / wrong shape / unknown version).
- `GameEvent` union: `sale`, `orderArrived`, `defect`, `delay`, `scandal`, `dropAnnounced`, `dropResult`, `dropPostponed`, `bills`, `overdrawn`, `recovered`, `bankrupt`, `hqUpgraded`, `firstSale`.

- [ ] Tests: `bills on week start`, `overdrawn then bankrupt after grace`, `recovering clears overdrawn`, `upgrade needs cash`, `save roundtrip equals state`, `rejects corrupt save`, `advanceDay does nothing after game over`.
